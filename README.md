# Y&B CRAVE

חנות הנשנושים והשתייה של Y&B: מזמינים מהטלפון, משלמים ב-PayBox / Bit / מזומן, ומקבלים עד החדר.

React + Vite + Tailwind CSS + lucide-react + Firebase (חבילת Spark החינמית).
האתר רץ ב-Netlify ומתעדכן לבד בכל push לענף `main`.

---

## מה יש באתר

**ללקוחות:** קטלוג מסודר לפי קטגוריות עם סרגל דביק, חיפוש, סינון לפי תקציב (עד 5 / 10 / 20 ₪), הרכבת שקית חמצוצים, קומבואים, טופס הזמנה (שם, טלפון ישראלי, מספר חדר, הערה), תשלום ב-PayBox עם חובת צילום אישור, Bit עם צילום לא חובה, או מזומן עם עודף. אחרי השליחה: מספר הזמנה וסטטוס חי. כל לקוח רואה רק את ההזמנות שלו.

**למנהלים (אין אליו קישור באתר):** נכנסים בלחיצה אחת על הלוגו Y&B ואז, תוך 4 שניות, שתי לחיצות מהירות על "פתוח עכשיו" / "סגור". (גם הכתובת `/admin` עובדת, ומוגנת בסיסמה.) הזמנות והעברות בלייב, אישור או דחיית תשלום מתוך צילום המסך (עם סיבה), ניהול מנהלים והרשאות, מוצרים / מחירים / תמונות / מלאי / קטגוריות, מתג פתוח-סגור, מספר להעברות, וסיכום כספי עם חלוקה 50/50 בין Y ל-B אחרי עלות סחורה.

**רקע וידאו:** שלושת הקליפים נמצאים ב-`public/media` (דחוסים לכ-100–350KB). בכל החלקה הרקע חותך לקליפ הבא עם זום והבזק, וגלילה מהירה מאיצה אותו. רק קליפ אחד מתנגן בכל רגע, ובטלפון במצב חיסכון / "הפחתת תנועה" מוצגת תמונה קבועה.

**תשלום:** הכפתור "פתיחת PayBox/Bit לתשלום" מעתיק את המספר ופותח את האפליקציה (באנדרואיד ישירות, באייפון דרך דף האפליקציה). אפליקציות התשלום לא מאפשרות לקישור רגיל למלא מראש מספר וסכום בחשבון פרטי, לכן הסכום מוצג גדול על המסך. אם תפתחו קישור תשלום עסקי או קבוצת PayBox, מדביקים אותו בדשבורד ← הגדרות והכפתור יפתח אותו.

**השרת (עובד מיד, בלי הגדרות):** כשהאתר רץ ב-Netlify, ההזמנות, המלאי, ההגדרות והמנהלים נשמרים בשרת של האתר (Netlify Functions + Netlify Blobs, בתיקייה `netlify/`). כל הטלפונים רואים את אותם נתונים. הכניסה למנהלים היא בקוד אישי (קוד ההתחלה של המנהל הראשי: `2580` — להחליף בהגדרות). מנהל ראשי מוסיף מנהלים בטאב "מנהלים" עם שם וקוד משלהם.

**התראות:** מנהלים מפעילים פעם אחת בטאב ההזמנות ומקבלים התראה על כל הזמנה חדשה, גם כשהאתר סגור. לקוח מפעיל במסך ההזמנה ומקבל התראה כשהתשלום אושר, כשההזמנה מוכנה וכשהיא יוצאת לחדר. באנדרואיד זה עובד ישר מהדפדפן; באייפון צריך קודם "שיתוף" ← "הוספה למסך הבית" ולפתוח מהאייקון.

**עמוד המנהלים הראשון:** למעלה פתיחה וסגירה של החנות (כשסגור, לקוחות רואים את המוצרים אבל לא יכולים להזמין), ומתחת כל ההזמנות הפתוחות ברשימה אחת בגדול. לקוח רואה מסך מלא בכל פעם שההזמנה שלו מתקדמת.

**מוצרים:** מוצר שאזל נשאר במקום שלו, באפור עם איקס אדום. בטאב "מוצרים" לחיצה ארוכה על מוצר בוחרת כמה מוצרים יחד, ואז אפשר למחוק את כולם או לתת לכולם אותו מחיר.

**מצב דמו:** כשמריצים מקומית בלי השרת, הכל נשמר רק בדפדפן (קוד `2580`).

## חיבור Firebase (לא חובה)

השרת המובנה ב-Netlify כבר מספיק. Firebase הוא חלופה למי שמעדיף כניסה באימייל וסיסמה; כשמגדירים אותו, האתר עובר אליו אוטומטית.

1. **פרויקט:** נכנסים ל-[console.firebase.google.com](https://console.firebase.google.com) ← Create project (אפשר בלי Analytics). נשארים בחבילת Spark.
2. **מסד נתונים:** Build ← Firestore Database ← Create database ← Production mode ← מיקום `eur3`.
3. **חוקי אבטחה:** באותו מסך, לשונית **Rules**: מוחקים הכל, מדביקים את כל התוכן של הקובץ [`firestore.rules`](firestore.rules) ולוחצים **Publish**. החוקים האלה הם מה שמונע מכל אחד שאינו מנהל לראות הזמנות, טלפונים וצילומי תשלום, או לשנות מחירים.
4. **התחברות:** Build ← Authentication ← Get started ← Sign-in method. מפעילים:
   - **Email/Password** (למנהלים)
   - **Anonymous** (ללקוחות, כדי שכל אחד יראה רק את ההזמנה שלו)
   
   ובלשונית Settings ← Authorized domains מוסיפים `yb-sell-nosh.netlify.app`.
5. **המנהל הראשי:** Firestore ← Start collection ← שם: `admins` ← Document ID: **האימייל שלכם באותיות קטנות** ← שדות: `name` (string) = השם, `role` (string) = `owner`.
6. **פרטי החיבור:** ⚙️ Project settings ← Your apps ← `</>` ← רושמים אפליקציה ← מעתיקים את ה-`firebaseConfig`.
   ב-Netlify: Project configuration ← Environment variables, מוסיפים:
   `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`, `VITE_FIREBASE_APP_ID`
   ואז Deploys ← Trigger deploy.
7. **כניסה ראשונה:** נכנסים ל-`/admin` ← "כניסה ראשונה? יצירת סיסמה" עם אותו אימייל ← מאשרים את מייל האימות ← לוחצים "העלאת הקטלוג".

מנהלים נוספים: המנהל הראשי מוסיף אותם בטאב "מנהלים" (שם + אימייל), והם נכנסים בדיוק כמו בשלב 7.

> תמונות מוצרים שמועלות מהדשבורד נשמרות בקולקציה `productImages` (כולם קוראים, רק מנהלים כותבים) — זה כבר בתוך `firestore.rules`.

> **למה אין `storage.rules`?** Cloud Storage של Firebase דורש היום חבילה בתשלום (Blaze). לכן צילומי התשלום נדחסים בטלפון של הלקוח לכ-100–300KB ונשמרים בקולקציה נפרדת ב-Firestore (`paymentProofs`), שרק מנהלים יכולים לקרוא. בהגדרות יש כפתור שמוחק צילומים של הזמנות ישנות כדי לשמור על המסד קטן.

> מפתח ה-Web של Firebase אינו סוד (הוא תמיד גלוי בדפדפן). ההגנה האמיתית היא חוקי ה-Firestore משלב 3.

## תמונות אמיתיות למוצרים

שלוש דרכים, מהמהירה לאיטית:
1. **צילום מהיר בדשבורד:** מוצרים ← "צילום מהיר של המלאי". המצלמה נפתחת, מצלמים, והמוצר הבא עולה לבד. התמונה נדחסת בטלפון ונטענת באתר רק כשהמוצר מופיע על המסך.
2. **קבצים בריפו (הכי מהיר לגולשים):** קובץ בשם ה-id של המוצר בתיקייה `src/assets/products/` (למשל `bamba.jpg`, `coke.webp`). רשימת ה-id נמצאת ב-`src/data/catalog.js`.
3. **קישור לתמונה:** מוצרים ← לוחצים על מוצר ← "קישור לתמונה".

מוצר בלי תמונה מוצג עם ציור אריזה זמני.

## העלאה בחינם

**Netlify (כבר מחובר):** כל push ל-`main` בריפו הזה עולה לאוויר תוך כחצי דקה. ההגדרות בקובץ `netlify.toml`.

**Vercel (אם רוצים במקום):** vercel.com ← Add New ← Project ← מייבאים את הריפו `yb-crave` מ-GitHub ← Framework: Vite ← מוסיפים את אותם משתני `VITE_FIREBASE_*` ← Deploy. הקובץ `vercel.json` כבר דואג שהנתיב `/admin` יעבוד. לא לשכוח להוסיף את הדומיין של Vercel ל-Authorized domains ב-Firebase.

## איפה משנים מה

| מה | איפה |
|---|---|
| מספר להעברות, קישורי PayBox/Bit, וואטסאפ | `/admin` ← הגדרות (ברירת מחדל ב-`src/config.js`) |
| מוצרים, מחירים, תמונות, מלאי, קטגוריות | `/admin` ← מוצרים |
| הקטלוג ההתחלתי | `src/data/catalog.js` |
| חוקי אבטחה | `firestore.rules` |

הרצה מקומית: `npm install` ואז `npm run dev`.
